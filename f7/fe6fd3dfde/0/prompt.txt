Go with Path 1, and here's why
                                                                              
  The current setup is fragile. scripts/cron-sync.sh runs on your laptop      
  (DASHBOARD_DIR is the local clone path, not a fresh checkout), via launchd, 
  and SSH-polls the VM for data before deploying. That means:                 
  - Laptop asleep or off-VPN → no deploy                    
  - Laptop's local repo on a different branch or stale → deploys wrong bits
  - The newly-added VM-side sync-monitoring.sh is now pushing to main      
  independently, but Vercel has no way to know                                
                                                                              
  You've got two deployers racing each other with different sources of truth. 
  That's a bug factory.                                                       
                                                            
  Fix: connect Vercel to GitHub, root dir                                 
  projects/2026-03-22_autoresearch-trading-dashboard/dashboard, then set this
  as the Ignored Build Step (Vercel Settings → Git → Ignored Build Step):     
                                                            
  git diff --quiet HEAD^ HEAD --
  projects/2026-03-22_autoresearch-trading-dashboard/dashboard                
  
  Vercel convention: exit 0 skips, exit 1 builds. git diff --quiet returns 0  
  when there's no diff in that path — perfect semantic match. Unrelated
  commits (the 99% of pushes that don't touch the dashboard) get skipped for  
  free. Data-only commits from sync-monitoring.sh touch     
  public/data/monitoring/ which IS under that path, so those correctly trigger
   builds.

  Retirement sequence:                                                        
  1. Connect Vercel ↔ GitHub, set root dir + ignored build step
  2. Push a trivial change to confirm auto-deploy works (can be a comment-only
   commit to live-monitoring.tsx just to prove it)                          Confirm main's 393e449 builds and the /live-monitoring tab shows real VM 
  data                                                                       
  4. Only after that works end-to-end: disable the laptop launchd entry and   
  delete cron-sync.sh                                                      
                                                                              
  Why not Path 2 (CLI-on-VM): fewer moving parts, yes — but you'd have to put
  a Vercel token on the VM (another secret to rotate), the VM would need      
  vercel CLI + Node, and builds would happen on the VM instead of on Vercel's
  build infra (slower, less observable, more surface area). It only wins if   
  you truly can't git-connect, which isn't the case here.   

  Build minute concern: You mentioned 108 commits ahead of main earlier. With 
  the ignored build step, only commits touching the dashboard dir actually
  build. VM sync-monitoring fires every 15min → data changes → build. That's  
  ~96 deploys/day maxading is active. Vercel hobby = 6000
  build-minutes/month; if each build is ~2 min you'd be at ~5800/month running
   24/7. Tight but inside limits. If it bites, batch the sync to hourly (0 * *
   * *) and you're at ~24 deploys/day with 30x headroom.
